<p className="lead">
  Tailwind로 기사나 문서, 블로그 글의 스타일을 꾸미려면 글꼴과 여백을 세심하게 살피고
  복잡한 사용자 정의 CSS를 작성해야 하는 경우가 많았습니다.
</p>

Tailwind는 기본적으로 문단, 제목, 목록 등에 적용되는 브라우저 기본 스타일을 제거합니다. 앱 화면을 만들 때는 기본 스타일을 되돌릴 필요가 줄어 편리하지만, CMS 편집기나 마크다운 파일에서 가져온 콘텐츠에 _서식만 적용하려는 경우_에는 의외로 느껴질 수 있습니다.

그래서 다음과 같은 질문을 자주 받습니다:

> Tailwind는 왜 `h1` 요소의 기본 스타일을 없애나요? 이 기능을 끄려면 어떻게 해야 하나요? 그러면 다른 기본 스타일도 모두 없어지나요?

그런 고민은 이해하지만, 기본 스타일을 끄는 것만으로 원하는 결과를 얻기는 어렵습니다. 대시보드에서 `p` 요소를 쓸 때마다 불필요한 여백을 지우고 싶지는 않을 것입니다. 블로그 글도 브라우저 기본 스타일에만 맡기기보다는 _보기 좋게_ 꾸미고 싶을 것입니다.

`@tailwindcss/typography` 플러그인은 기본 스타일을 비활성화하는 불편 없이 콘텐츠에 필요한 서식을 제공합니다.

일반 HTML 블록에 `prose` 클래스를 추가하면 읽기 좋은 문서로 표시할 수 있습니다:

```html
<article class="prose">
  <h1>치즈 마늘빵: 과학은 무엇을 말할까요?</h1>
  <p>
    오랫동안 부모들은 아이들에게 치즈 마늘빵을 먹는 즐거움을 이야기했습니다.
    따뜻한 빵과 고소한 치즈는 식탁에서 빠질 수 없는 조합이 되었습니다.
  </p>
  <p>
    이 문단은 블로그 본문에서 문단 사이의 간격과 줄바꿈을 확인하기 위한 예제입니다.
  </p>
  <!-- ... -->
</article>
```

플러그인의 사용법과 기능은 [공식 문서](https://github.com/tailwindcss/typography/blob/main/README.md)를 확인하세요.

## 아래에서는 무엇을 살펴볼까요?

이제부터는 플러그인의 표시 결과를 확인하기 위한 예제 문장이 이어집니다. **굵은 글씨**, 순서 없는 목록, 순서 있는 목록, 코드 블록, 인용문, _기울임꼴_ 등 다양한 서식을 포함합니다.

이런 사용 사례를 살펴보는 이유는 다음과 같습니다:

1. 별도 설정 없이도 모든 요소가 보기 좋게 표시되어야 합니다.
2. 첫 번째 이유가 이 플러그인의 가장 중요한 목적입니다.
3. 두 항목보다 세 항목짜리 목록이 자연스러워 보여 예제를 하나 더 넣었습니다.

이제 다른 수준의 제목을 살펴보겠습니다.

### 글의 서식은 쉽게 적용할 수 있어야 합니다

위 문장은 제목 예제입니다. 스타일이 잘 적용되었다면 적절한 크기와 간격으로 표시될 것입니다.

글의 서식에 관해 누군가 이런 말을 했습니다:

> 콘텐츠를 보기 좋게 전달하려면 글꼴과 여백이 중요합니다. 읽기 편하게 다듬으면 내용도 더 잘 전달됩니다.

- 이번 예제에서는 항목을 짧게 작성합니다.

## 제목이 연속으로 나오면 어떨까요?

### 이런 경우의 간격도 확인해야 합니다

때로는 제목 바로 아래에 다른 제목이 나옵니다. 이때는 두 번째 제목의 위쪽 여백을 줄여야 자연스러울 수 있습니다. 문단 다음에 제목이 나올 때보다 제목끼리의 간격이 좁은 편이 보기 좋기 때문입니다.

### 문단 다음에 제목이 나올 때는…

앞에서 설명한 것처럼 문단 뒤의 제목에는 여백이 조금 더 필요합니다. 이제 복잡한 목록의 표시 결과를 살펴보겠습니다.

- **목록 항목 안에도 제목을 넣을 수 있습니다.**

  이런 형식은 보기 좋지만 스타일과 간격을 맞추기가 까다로울 수 있습니다.

  항목 하나에 문단을 두세 개 넣기도 합니다. 문단 사이, 항목 제목 아래, 서로 다른 항목 사이의 간격을 모두 자연스럽게 맞춰야 합니다. 읽기 어렵다면 내용을 나누는 것도 방법입니다.

- **목록이므로 두 번째 항목도 추가합니다.**

  앞 항목에서 설명한 내용을 실제 목록 형태로 확인하기 위한 예제입니다. 여러 항목이 있어야 스타일을 조정할 때 간격을 비교하기 쉽습니다.

- **세 번째 항목도 살펴봅니다.**

  두 항목으로도 충분할 수 있지만, 세 번째 항목이 있으면 반복되는 형태를 확인하기 좋습니다. 이제 <kbd>Enter</kbd> 키를 눌러 다음 문단으로 넘어갑니다.

이런 목록 뒤에는 바로 제목을 넣기보다 문단을 덧붙이면 흐름이 자연스러워집니다.

## 코드도 기본 상태에서 읽기 좋아야 합니다

코드 구문 강조에는 [highlight.js](https://highlightjs.org/)나 [Prism](https://prismjs.com/) 같은 도구를 사용할 수 있습니다. 구문 강조가 없더라도 코드 블록 자체는 _읽기 편하게_ 표시되어야 합니다.

아래는 글을 처음 작성할 당시의 `tailwind.config.js` 설정 예제입니다:

```js
module.exports = {
  purge: [],
  theme: {
    extend: {},
  },
  variants: {},
  plugins: [],
}
```

코드의 들여쓰기와 간격을 확인해 보세요.

### 중첩된 목록은 어떨까요?

목록이 여러 단계로 중첩되면 읽기 어려워지기 쉽습니다. 그래서 중첩을 제한하는 편집기도 있지만, 필요한 경우에는 올바르게 표시할 수 있어야 합니다.

1. **중첩 목록은 꼭 필요한 경우에만 사용하세요.**
   - 정리되어 보이더라도 실제로는 복잡한 형태가 되어 읽기 어려울 수 있습니다.
   - 화면의 탐색 메뉴도 가능한 한 단순한 구조로 유지하세요.
   - 소스 코드의 폴더도 지나치게 깊게 나누지 않는 편이 좋습니다.
2. **두 번째 항목에서도 간격을 확인합니다.**
   - 두 단계보다 깊은 중첩은 신중하게 사용하세요.
   - 세 단계가 되면 구조를 이해하기가 더 어려워집니다.
   - 네 단계 이상이라면 내용을 다시 나누는 것이 좋습니다.
3. **세 번째 항목으로 반복 형태를 확인합니다.**
   - 독자가 쉽게 읽을 수 있도록 중첩을 줄이세요.
   - 복잡한 목록은 한눈에 살펴보기 어렵습니다.
   - 표시가 가능하더라도 반드시 사용할 필요는 없습니다.

마크다운 목록에서는 항목에 문단이 여러 개 있을 때만 `<li>` 안에 `<p>` 요소가 생깁니다. 따라서 두 경우 모두 간격이 자연스러운지 확인해야 합니다.

- **여기에 중첩 목록을 하나 더 넣습니다.**

  이번에는 두 번째 문단도 추가했습니다.

  - 이 항목에는 `<p>` 요소가 없습니다.
  - 각 항목이 한 줄로만 이루어져 있기 때문입니다.

- **두 번째 최상위 항목에서는 문단이 들어갑니다.**

  이 문단과 하위 목록 사이의 간격도 확인하세요.

  - 이 항목에는 두 번째 문단을 추가했으므로 `<p>` 요소가 생깁니다.

    이것이 두 번째 문단입니다.

  - 목록의 형태를 확인할 수 있도록 항목을 하나 더 추가했습니다.

- 마지막 항목에는 중첩 목록이 없습니다.

이 문단으로 중첩 목록 예제를 마칩니다.

## 설명 목록도 살펴봅니다

설명 목록은 용어와 설명을 짝지어 표시할 때 사용합니다. 이 플러그인은 2020년에 처음 공개되었고, 설명 목록 지원은 그로부터 3년 뒤 추가되었습니다. 자주 묻는 질문을 표시할 때도 유용합니다.

<dl>
  <dt>마크다운은 무엇인가요?</dt>
  <dd>
    간단한 기호로 제목, 목록, 링크 등의 서식을 작성하는 문법입니다.
    복잡한 HTML을 직접 쓰지 않아도 문서를 구성할 수 있습니다.
  </dd>
  <dt>MDX에서는 무엇을 할 수 있나요?</dt>
  <dd>
    마크다운 본문 안에 컴포넌트를 넣을 수 있습니다.
    안내 상자나 실행 가능한 코드 예제처럼 다양한 요소를 함께 보여 줄 수 있습니다.
  </dd>
  <dt>설명 목록은 언제 사용하나요?</dt>
  <dd>
    용어 사전, 기능 설명, 자주 묻는 질문처럼 제목과 설명이 한 쌍인 내용에 적합합니다.
    설명이 여러 문장으로 길어져도 항목 사이의 간격을 유지해야 읽기 편합니다.
  </dd>
</dl>

## 그 밖의 요소도 확인합니다

[Tailwind CSS 웹사이트로 이동하는 링크](https://tailwindcss.com)처럼 본문 안의 링크도 스타일이 필요합니다. 글을 읽는 흐름을 방해하지 않으면서 클릭할 수 있다는 점이 드러나야 합니다.

표도 다음과 같이 표시할 수 있습니다:

| 선수 | 출신 지역 | 대표 기술 |
| --- | --- | --- |
| 브렛 하트 | 캐나다 캘거리 | 샤프슈터 |
| 스톤 콜드 스티브 오스틴 | 미국 오스틴 | 스톤 콜드 스터너 |
| 랜디 새비지 | 미국 새러소타 | 엘보 드롭 |
| 베이더 | 미국 볼더 | 베이더 밤 |
| 레이저 라몬 | 미국 출루오타 | 레이저스 에지 |

`<span>` 요소나 `@tailwindcss/typography`를 설명할 때 사용하는 인라인 코드도 자연스럽게 표시되어야 합니다.

### 제목 안에도 `code`를 넣을 수 있습니다

제목 안에 코드가 들어가면 크기와 간격을 맞추기 까다로울 수 있습니다. 그래도 _백틱으로 코드를 감싸는_ 문법으로 간편하게 표현할 수 있습니다.

[`tailwindcss/docs`](https://github.com/tailwindcss/docs) 저장소를 소개할 때처럼 링크 안에 `code`를 넣을 수도 있습니다. 코드 아래의 밑줄과 링크 표시가 함께 어떻게 보이는지 확인하세요.

#### 네 번째 수준의 제목인 `h4`입니다

더 깊은 제목 수준이 필요할 때도 있지만, `h5`나 `h6`를 쓰기 전에 문서 구조를 단순하게 정리할 수 있는지 살펴보세요. 제목 수준이 많아지면 독자가 흐름을 따라가기 어려워집니다.

`h4`는 본문과 비슷한 크기이므로, 더 작은 제목을 추가하기보다는 문서나 구역을 나누는 편이 읽기 좋을 수 있습니다.

### 제목이 연속으로 나오는 경우를 다시 확인합니다

#### `h4`에서도 간격이 자연스러운지 살펴보세요

위 제목들의 크기와 여백이 적절하면 연속된 제목도 명확하게 구분됩니다.

문서 끝에 제목만 남으면 화면이 불균형하게 느껴질 수 있습니다. 마지막 문단을 넣으면 내용의 흐름을 자연스럽게 마무리하고 아래쪽 여백도 확인할 수 있습니다.

여기까지 다양한 마크다운 요소의 표시 예제를 살펴보았습니다.
